Who does what

A software factory

Behind the board, ConsensFlow is a small civilization at work. The chief plans, and hands each task to a member of the role it needs: workers build, frontend designers design and build screens, architects design the software, researchers and advisors bring findings, reviewers and testers check finished work, integrators land what was accepted, and the image designer draws. When a check finds something, the chief sends it back into the same window, so the follow-up continues where the task stopped. You set the goal and make the calls that are yours. What comes out is software.

One goal, under way

The shopping list of the demo project, as far as it has gone: your goal in the chief's terminal, the messages the board carried for two tasks, the API (T-2) and its review (T-3), and the chief's note to you. The page, T-4, is still under way. T-2's own messages are in its task, shown open under What it does.

  1. Goalyou → chief, in its terminal

    “The pantry app needs a shopping list: add items, check them off, clear what's done. Keep the list on the server, and have the API reviewed before the page is built on it.”

  2. Request 1chief → the board · T-2, for a standard worker

    The chief reads the routes the app has and writes the brief: three routes, where to keep them, tests beside theirs, npm test before reporting. It adds T-4, the page, for the frontend designer, to wait until T-2 is accepted. @gpt-6-1-terra-high, a standard worker on Codex, is free: T-2 opens in a fresh Codex window.

  3. Question@gpt-6-1-terra-high → chief · T-2 waits

    “Should clearing delete the checked rows, or keep them and mark them cleared? items keeps its history with a deleted_at column; the list could do the same.”

  4. Answerchief → @gpt-6-1-terra-high · T-2 goes on

    “Delete them. The list is a scratch pad: nothing reads old entries, and items keeps the history that matters.”

  5. Result 1@gpt-6-1-terra-high → chief · T-2 done, for the chief to decide

    “Done. The three routes are in server/routes/list.ts, mounted in server/app.ts. […] 15 new tests in server/routes/list.test.ts. npm test passes: 61 tests.”

  6. Reviewchief → the board · T-3, for a complex reviewer

    “Read the change for T-2 and the diff. Is it right, and is it tested?”

    @claude-opus-5-5-max, a reviewer on Devin, takes it. A review changes no file.

  7. Findings@claude-opus-5-5-max → chief · T-3 done

    “Not ready yet: two findings. Clearing deletes row by row, outside a transaction; a failure halfway leaves the list half cleared. PATCH with an unknown id throws, so the client gets a 500; it should get a 404. Otherwise the routes match the brief, and each has its tests.”

  8. Request 2chief → @gpt-6-1-terra-high · T-2 reopened, back into the same window

    “The review (T-3) found two things to fix before I accept this: clear it in one transaction, and answer 404 for an id that does not exist. Add a test for each, run npm test, and report.”

  9. Result 2@gpt-6-1-terra-high → chief · T-2 done again

    “Both fixed. Clearing runs in one transaction: a failing delete rolls the whole clear back. An unknown id answers 404. 3 new tests. npm test passes: 64 tests.”

  10. Acceptedchief · T-2 and T-3 finished

    T-4, the page, was waiting on T-2: it starts now, in a window of its own, for the frontend designer.

  11. Notechief → you, on the board

    “The shopping list API is in: T-2, reviewed in T-3. The page is under way in T-4.”

And it goes on. For the expiry reminders, the chief had a question of its own, how to handle time zones, and put it to an advisor as T-6. The advice came back, and one plan put the next five tasks on the board: store each household's time zone, T-8; the reminders themselves, T-9, waiting on the page, the time zone and the design; the README, T-10; the job's design, for the architect, T-11; and the mail service, for a researcher, T-12. It is all there in the first capture above, in the chief's terminal.

One task's path

How it works

Everything happens in one window: the board on the left, the agents' terminals on the right. Here is one task's path across the board.

  1. Backlog
  2. Queued
  3. Working
  4. Waiting
  5. Done
  6. Finished
T-4 Shopping list page Working
    • Backlog

    The chief puts a task on the board

    A brief written for someone who has never seen the project, for the role the work needs, and for a worker, advisor, reviewer or tester its tier: critical, complex, standard or light. A task can wait for others to be accepted first.

    • Queued

    An available member takes it

    ConsensFlow picks an available member of that role, and of that tier where the role has one, never a name, so the work is shared across the staff.

    • Working
    • Waiting

    It works in a terminal of its own

    A fresh terminal of the member's harness, with your login. Open it from the member's row to watch, or tell it something: a tell reaches the window at its next rest. A question to the chief puts the task in Waiting until the answer comes.

    • Done
    • Finished

    The result comes back to the board

    The chief decides: accept it, or send it back to the same window with what must change. The window closes, and its conversation is kept, so a follow-up continues where it stopped.

What you will notice. Each one is told in full under What it does.

  • Nine roles

    Frontend designers, architects, researchers and integrators join workers, advisors, reviewers, testers and the image designer.

  • A board grouped by role

    The new dark board groups the staff by role, and each task says how long it has been in its state.

    Settings → Agents is gone: New project, Project settings and Switch chief read each installed harness's models as they open, and members are named by their model.

  • A plan in one command

    cf task add --plan plan.md puts a plan and its order on the board at once.

  • Muse Code, the fifth harness

    Meta's Muse Code joins Claude Code, Codex, Pi and Devin, for the chief or its staff.

  • A meeting with the chief

    Start meeting holds the staff's messages while you talk with the chief; they come in one at a time after.

  • Compaction, and Claude Code's extras

    Project settings sets when members compact their conversations, and whether Claude Code guesses your next prompt or uses its advisor tool.

  • Messages at the right moment

    A tell reaches a window at its next rest. Notes that need the chief are typed into its window; the rest wait in cf inbox.

  • Resume after a quit or update

  • Install from a terminal

    One line installs the latest release on a Mac or on Windows, and upgrades the one you have, once it has quit.

In the app

What it does

The staff

One chief, a whole staff
Give the chief your goal in its terminal. It breaks the work into tasks, does what is its own, and hands the rest to the staff you picked for the project.
Nine roles
Workers, frontend designers, architects, researchers, advisors, reviewers, testers, integrators and an image designer, on Codex. The chief gives each member work for its role, and what the role makes comes back, as the factory above draws it. Researchers, advisors and reviewers change no project files; testers change no product code.
Work by tier
For worker, advisor, reviewer and tester tasks, the chief asks for a tier (critical, complex, standard or light), and each such task gets a new window of a member of that role and tier. The other roles need no tier.
Named by their model
Pick a member's harness, one of its models and, where offered, an effort: the lists are read from the installed harnesses when the dialog opens. A member is named by its model, as @gpt-6-1-terra-high is.

Backups and Vacation

A backup for a member
Give a member an optional backup on any harness or model. New tasks go to free members first. When a member cannot run a task—for example because its quota is out, its login or billing is refused, its model moved or stays busy, its harness cannot open, or the member needs an edit—its free backup can take it, whether it is new or was already given. Work in progress starts over in a fresh window, with a warning to check for partial changes. Tasks given by name, follow-ups, the chief's own tasks and tasks you paused do not move. The chief and the image designer have no backup. On the board, a member and its backup share one team lane and one status. Open the team to see each one.
Vacation
On the board, Vacation sends a member and its backup together; in Project settings, you can send either one. Vacation stops new tasks; work already in a window finishes there. A member on Vacation is not covered by its backup.
Quota-aware
A member works up to 100% of its quota and waits when its harness says it is out, keeping its work in its window until the reset. If the account's quota is renewed early, Try again now brings it back; for harnesses with a shared login, it also brings back chiefs and members across projects.

Do with your own hands

The chief does the work itself
Turn it on in New project, Project settings or the chief's pane, and the chief does your work itself, using the board only when you ask. Work already on the board continues.
The board when you want it
Ask for a task and the chief puts it on the board as before. It can read the board's guide in parts with cf guide.

The chief

Any harness, any of its models
In New project, pick the chief's harness, its model and, where offered, an effort. The lists are read from the installed harnesses when the dialog opens. Settings → Harnesses shows which are installed, their versions, and whether ConsensFlow is set up for each; the versions that work are on the Supported versions page.
Switch the chief anytime
Move the chief to another model or harness. The new chief starts with a handoff: what is on the board, your last words, and the history of the chiefs before it.
A meeting with the chief
Start meeting, on the chief's card, holds the staff's results and questions while you talk with it, shown on the board as held. Stop meeting and they go in one at a time, as the chief comes to rest, questions first.

The board

A board you can read
The dark board groups the staff by role. Each task shows who has it, where it stands, and how long it has been in that state. Open a task to read its brief, result and messages, and see what the agent did.
Each task in its own window
A task opens a fresh terminal of its agent's harness, and the window closes when the work is done. Its conversation is kept, so a follow-up continues where it stopped.
Plans with an order
A task can wait for others to be accepted first, so a plan runs in its own order, in parallel where it can. The chief can add a plan and its dependencies in one command with cf task add --plan plan.md.

Specs

Big work becomes a spec
With specs on, the chief plans big work as a spec, with Specmint, and puts each phase on the board as tasks, in order. A small ask still goes straight to the board.
On for every project, or for one
Settings → Specs sets whether a chief plans big work as specs in every project that doesn't say otherwise, in which folder and with which variant of Specmint. A project's own Specs settings win.
Read them in the app
The Specs button on the board opens the project's specs folder: its tree, and each spec as Markdown, Mermaid diagrams included.

History

Everything a participant said
History, on a window's head and on the chief's card, opens everything ConsensFlow keeps of that participant's conversations. Search it. It follows your system's light or dark appearance.
The chief reads it too
After you switch the chief, the new one reads what you and the chiefs before it said with cf history, and searches it with --find.

Project settings

One dialog for each project
Project settings holds the project's staff and backups, own hands, human approval, wake-up calls and specs. New project offers the same, so a project can start with them set. Right-click a project in the sidebar to rename it, or to give it a one-line description that no agent is told.
Compaction
A size from 250,000 to 1,000,000 tokens at which each member's harness compacts its conversation, or the harness's own point. A new project starts at 300,000.
Prompt suggestion and the advisor tool
Prompt suggestion controls Claude Code's next-prompt guess for the chief and members; Advisor tool controls Claude Code's own advisor tool for members. Both are off by default; when on, Claude Code follows its own settings.
Wake-up calls
A chief that stopped while work is left carries on: you set how often it is asked, and what it says.

You stay in charge

Tell, pause and resume
A tell lets a member keep working and reaches its window at the next rest. A pause stops the task and can ask a question; resume sends it on in the same window.
Notes without interruption
ConsensFlow types notes that need the chief's attention into its window. Other status notes are there for the chief in cf inbox.
Resume after a quit or update
Resume a project to bring its windows back on their conversations. A member cut mid-turn is told to go on; a window that cannot come back has its task paused, with the reason.
Your approval, if you want it
Turn on human approval for a project, and every message between agents waits for you to pass it on.

Before you start

Your data, and what the agents can do

  • ConsensFlow keeps its data in ~/.consensflow (on Windows, %USERPROFILE%\.consensflow).
  • It never sees your passwords: each agent uses its own harness's login.
  • Agents work with full permissions in their windows, as they would if you ran them yourself. Your protection is the review, the chief's acceptance and, if you turn it on, your approval. Use ConsensFlow on projects kept in version control.
  • Every agent, the chief and its staff alike, starts with its harness's MCP servers and connectors (your browser, your accounts, your IDE), skills, settings and customizations, as it would if you ran it yourself. The staff use them with full permissions while you aren't watching, so keep in a harness only what you would let any agent use.
